# Install, Uninstall, And Reinstall Test Matrix

## Required Sandbox

- Dedicated CloudBoss test subscription, tenant, resource group, and portal environment.
- Customer install packages generated by the staging control plane.
- Disposable resource names, including a new Key Vault name for every reinstall package.
- Accounts capable of Azure deployment and removal plus Microsoft Graph validation.

## Lifecycle Scenarios

| ID | Scenario | Expected result |
| --- | --- | --- |
| L01 | Clean install, validate, finish | Runtime passes validation, final evidence is created, portal reaches completed. |
| L02 | Clean install, uninstall, generate new package, reinstall | Old resource group is absent, old vault remains unpurged, new package deploys with a new vault name. |
| L03 | Repeat L02 three times | No naming, ownership, portal-state, evidence, or resume drift. |
| L04 | Failed partial install, cleanup, reinstall | Owned partial resource group is removed and new package installation succeeds. |
| L05 | Close installer during a non-destructive phase and resume | State resumes without tokens or restored destructive approval. |
| L06 | Portal unavailable after successful Azure action | Local action remains successful and callback stays queued for retry. |
| L07 | Existing custom domain returns HTTP 200 but points to an older app | Runtime validation fails and no `runtime_configured` or `install_completed` event is emitted. |
| L08 | New App Services return the Azure default page | Portal validation fails and Finish remains blocked. |
| L09 | Runtime `/health` returns a different deployment export ID | API identity validation fails and the mismatch is recorded without secrets. |

## Removal Safety Scenarios

| ID | Scenario | Expected result |
| --- | --- | --- |
| R01 | Inventory only | No delete command runs; preview artifact lists owned resources and retention. |
| R02 | Wrong subscription or tenant | Inventory/removal blocks before deletion. |
| R03 | Resource group missing | Validation reports already absent; rerun is successful and idempotent. |
| R04 | Resource group ownership tag missing or changed | Removal blocks. |
| R05 | Unrelated resource inserted into the group | Removal blocks. |
| R06 | Active Azure deployment | Removal blocks. |
| R07 | Incorrect typed confirmation | Removal blocks and no delete command runs. |
| R08 | PowerShell WhatIf | Removal reports skipped and no delete command runs. |
| R09 | Approved removal | Dedicated resource group is deleted and a cleanup artifact is written. |
| R10 | Key Vault retention disabled | Installer rejects the request; purge is never attempted. |
| R11 | Run cleanup again after success | Result reports already absent without failure. |
| R12 | Interrupt deletion and resume validation | Installer detects the live Azure state and does not duplicate unsafe work. |
| R13 | SharePoint content exists before and after uninstall | No SharePoint mutation occurs and content remains accessible through SharePoint. |
| R14 | Reinstall package reuses old vault name | Preflight blocks and requires a newly generated package. |
| R15 | Reinstall package uses a new disposable vault name | Preflight and deployment can proceed. |

## Evidence Assertions

Every scenario must confirm:

- No access token, secret, connection string, raw provider response, or document content appears in evidence.
- Preview and execution identify the same package, subscription, resource group, and inventory.
- Removed, retained, skipped, blocked, and failed items are explicit.
- Portal lifecycle and local evidence agree after queued callbacks are delivered.
- No customer SharePoint content or unrelated Azure resource changes.
